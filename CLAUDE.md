# D&D Character Sheet

Interactive D&D 2024 (Player's Handbook 2024) character sheet for iPad. It's a static React web app hosted on GitHub Pages and installed from Safari with "Add to Home Screen". It runs offline, and all character data stays on the device.

- Live: https://matiiq.github.io/mq-dnd-sheet/
- Repo: https://github.com/MatiiQ/mq-dnd-sheet (public, branch `main`)
- Design source: Claude Design canvas https://claude.ai/code/artifact/14f009f2-87d8-4f14-8590-3c89bac0558f (`project/Main.dc.html` = landscape sheet, `project/Portrait.dc.html` = portrait). The app reproduces its behaviour; read it with the Artifact tool, not WebFetch. Since the 2026-10-24 restyle the app's look (Tabletop tokens, Midnight & candlelight) no longer follows the canvas, which still documents behaviour.

## Layout

```
.github/workflows/deploy.yml   CI: test, build code/, publish code/dist to Pages (must stay at repo root)
code/                          the web app (run all npm commands here)
README.md                      user-facing overview and setup (root, not code/)
docs/                          local plans and audits, gitignored (the "plan N" references point here)
reference/                     condensed PHB 2024 rules data (markdown), gitignored
resources/                     PHB 2024 PDF, gitignored
```

`reference/` and `resources/` are copyrighted Player's Handbook material. They are in `.gitignore` and must never be committed, because the repo is public.

## Commands (from `code/`)

```sh
npm run dev      # Vite dev server on :5173, --host so the iPad can open it over Wi-Fi
npm test         # Vitest, every *.test.ts(x) under code/ (rules, catalog, storage, UI, scripts)
npm run build    # tsc --noEmit, tsc -p scripts (typechecks scripts/), then vite build into dist/
npm run preview  # serve dist/ with the service worker active
npm run icons    # regenerate public/icons/*.png (dependency-free PNG writer)
npm run srd      # rebuild src/data/srd/*.json and src/catalog/names.ts from the SRD 5.2.1 text (scripts/srd/README.md)
npm run pack     # build reference/build/phb-pack.json (PHB data for the device) and the check phrases, from reference/
npm run audit-catalog  # rebuild the pack, then catalog against the SRD text, reference/ and the app's code; fails on a missing input, a discrepancy not in reference/audit-known.json, a known one whose note changed or that is gone, or a changed grant hash
npm run check-phb  # build, then fail if dist/ or a tracked file holds PHB description text (needs reference/ and npm run pack)
npm run hooks    # once per clone: install the pre-push hook that runs audit-catalog (when reference/ exists) and check-phb on every pushed commit
```

`code/scripts/audit/` holds that audit: `catalog-audit.test.ts` also runs in `npm test`, and is skipped without the built pack and `resources/srd/srd.txt`, so CI runs only its fixture tests (`checks.test.ts`). After `npm run srd` or `npm run pack`, run `npm run audit-catalog`, then read `reference/build/audit-report.txt` (its first line gives the run time and the pack's `builtAt`). `AUDIT_UPDATE=1 npm run audit-catalog` accepts the current findings and grant hashes: it prints the keys added, removed and changed, copies the old list to `audit-known.json.bak`, and puts new keys in `todo`. The known list holds `accepted` (fine as they are), `todo` (real defects still to fix), each key with its note and a reason, and `grants` (a hash per entry). A green audit means nothing new, not a clean catalog: read `todo`. All these files stay in `reference/`, because they name and can quote PHB content.

`code/scripts/local/` (gitignored) holds PHB-side tests that need `reference/`; they don't exist in CI or on a clone without it, so a green CI says nothing about them.

Toolchain: Node 22+ (CI uses 22), React 19, Vite 8, TypeScript 7, Vitest 5. The app has no other runtime dependencies besides `@fontsource` (Fraunces and Figtree, latin subsets, bundled so they work offline).

## Deploy

Every push to `main` runs `.github/workflows/deploy.yml` (test → build → deploy-pages). Push only from the machine that holds `reference/`: the pre-push hook (`npm run hooks`) checks every pushed commit for PHB text, and on a clone without `reference/` it lets the push through unchecked. Pages source is "GitHub Actions". Vite uses `base: './'`, so the build works under any repo path. Installed Home Screen apps get the new version on their next online launch.

Conventions:
- State changes go through `update(patch)` from `useSheet()`. A patch is a partial `Character` or a function of the current one. Put rule logic in `logic.ts`, not in components.
- Persisted data is the `Character` object. Transient UI state (open forms, armed buttons, menu) lives in React state and is never saved.
- Styling: CSS classes and tokens in `styles.css`. Inline `style` only for one-off or computed values. Icons are inline stroke SVGs, not emoji.
- Touch targets are at least 44 px. Use real `<button>`/`<a>`/`<input>` elements, with `aria-label` on icon-only buttons.
- Numbers show a real minus sign (`fmt()` → `−1`).

## Storage and offline

- localStorage keys: `dnd-index-v3` (`{active, list:[{id,name,info}]}`) and `dnd-sheet-v3:<id>` (one `Character` per key). These match the design prototype's keys. `dnd-layout` (`auto`/`one`/`two`) holds the menu's layout override per device; it isn't part of a `Character` or the backup. `dnd-draft` (`{ v, step, answers }`, `DRAFT_VERSION` 1) holds the creator's unfinished answers, one at a time; not a `Character`, never in a backup; a draft that doesn't parse or has another `v` is dropped with a notice. `step` is a screen key (`'origin/background'`); an older draft's number maps through `OLD_STEP_KEYS`, an older Rolled draft's six scores become `rolled` (else its scores clear), and `firstDone` is accepted, never read. `DRAFT_VERSION` stayed 1 for the string step, so an older offline copy of the app discards a new draft as damaged (accepted). Existing saves are merged over `blankCharacter()`, so a missing or damaged field reads as blank. A new top-level key that every save must have needs `blankCharacter()`, both samples and a type, and a version step, because the frozen v2 fixture lacks it and must load unchanged; a later key is optional instead: absent by default, copied by `migrate()` and cleaned by `normalize()` (`castFx`). Real saves exist now, and the app writes `migrate()`'s result back on launch, so anything it drops is gone. Every character carries `v` (`SAVE_VERSION` in `defaults.ts`; a save without it is version 1). A new optional field needs no version. Reshaping, renaming or removing a saved field, or changing a value list `migrate()` checks (grant kinds and fields, `PROF_CATS`, defense kinds…), needs: bump `SAVE_VERSION`, add `STEPS[old]` in `migrate.ts` (old save → new, before the repair), add a fixture of the new format in `src/fixtures/`, and keep every old fixture passing. Save v2 (`SAVE_VERSION` 2, `STEPS[1]`, fixture `save-v2-multiclass.json`): `ch.cls/sub/clsId/subId`, `level`, `hdDie`, `prepMax` and `slotsOnShort` are gone; `classes` (`ClassRow`: `id` without `.`, `name`, `clsId`, `sub`, `subId`, `lvl`, `hd`, `prep`, optional `castAb`; the first row is the starting class; the character level is their sum), `levels` (`LevelRecord` history, oldest first; `base` records are the baseline and cannot be undone; `set` entries are checked against `LEVEL_KEYS`/`row.<id>.<field>`, an absent optional value stored as `''`; records that don't add up to the rows collapse to one base record with a notice), `conBase` (the CON modifier already inside `maxHp`/`origHp`; `migrate()` sets it on a v1 save or a missing/damaged one), `hdUsed` per die size (`{ 10: 1 }`, clamped per pool), `pactMax`/`pactLvl`/`pactUsed` (the Pact Magic pool, refilled by a Short Rest) and optional `Spell.cls` (the row that prepared it). `hdLast` (the die waiting for its heal) is optional and never loaded. `HpSnapshot.hdUsed` is `{ die, used }`. Grants from a class row use `from: 'class:<row id>'`. `load()` keeps a v1 save's raw text in `<key>:unreadable` before its first upgrade, because the step is one-way. A save with a `v` above `SAVE_VERSION` (a newer app's, opened by an older offline copy) has its raw text kept as `<key>:unreadable` before it opens, with a notice (`load()` in `storage.ts`). Plan 4 added `ch.clsId`/`ch.subId` (catalog ids matched to the typed class and subclass) and optional catalog fields on `Spell` and `Item`, each checked on load by `SPELL_FIELDS`/`ITEM_FIELDS` in `migrate.ts` (a bad value goes, never the entry). Plan 5 added `hands` (item ids in hand, oldest first, one entry per hand; changed only through `setHands`, trimmed by `normalize()`) and `mastery` (Weapon Mastery kinds, oldest first), plus optional `Attack.econ`/`Attack.group` (`ATTACK_FIELDS`) and `Spell.healMod`; every character has a computed Unarmed Strike, so the samples hold none. Plan 6 added `sections` (`{id, name}` in display order; an entry list, so a section needs a name, then duplicate ids and blank names go) and flat item fields `sec` (its section; one that is gone clears), `in` (the extradimensional container it sits in, one level deep) and `cp`…`pp` (a container's own coins), checked by `ITEM_FIELDS`; `fixContainers` then fixes the links between items. Item removal (`removeRef`) takes a removed container's contents out and moves its coins to the purse. Plan 7 added optional `Spell.dmgMod`/`dtypes` (`SPELL_FIELDS`) and `Spell.parts` (a list, cleaned part by part by `cleanParts` in `migrate()`; `isEntry` lets a spell's `parts` through), and `Item.load` (a weapon's loaded ammunition, checked by `fixLoads` in `normalize()` and `removeRef`); no migration step, all optional. `Spell.acOther` (`SPELL_FIELDS`; optional, no migration step): an AC spell cast on another creature runs but adds no AC, and a Concentration spell that isn't Self range has its active grants and entries (except `xdmg` and `aura`) not count on you (`effectCanTargetOther`). `slotsOnShort` makes `shortRest` clear every spell slot, for Pact Magic. `Sense.plus` (optional, no migration step): the range adds to the longest other sense of that name ("+60 if you already have Darkvision"), read by `mergedSenses`. Grants added the same way: kind `hpFlat` (a one-time maximum HP increase), `ac` with `acMode: 'dexCap'` (Medium armor's Dexterity cap), `prof` with `orExpert` (Expertise if already proficient), and speed `val: 'walk2'`. The catalog feature gaps (2026-11-05) added, all optional with no migration step: on `action`, `uses` (the catalog id of the feature whose counter the row shows; `resOfFeature`), `regainTo` (a Regain button, `regainTo()` in `logic.ts`), `dc`/`dcAb` (a save DC, `saveDc`); on `lightExtra`, `anyMelee` (Dual Wielder) and `weapon` (Crossbow Expert's `addMod` filter); on `dmgBonus`, `useAb` (Rage: Strength attacks only) and `spell` (a cantrip bonus for one spell, Agonizing Blast); on `xdmg`, `swap` (replaces the row it names, Foe Slayer); `note` on `resource`; `When` `'empty'` (no weapon in hand, no Shield); value term `hlvl` (half the level, rounded down). Choices: `ChoiceSpec.ifPick` (`'<choiceId>=<value>'`, `choiceActive`), the `feat:any` pool, and a `skill:proficient` pool that also offers the entry's own skills (`livePicks` drops a pick that left it). The creator's class fields (2026-11-09, all optional): `blurb` (the app's own words, in the overlay), `likes`/`complexity` (the Class Overview, PHB p.33) and `stdArray` (the Standard Array by Class, PHB p.38; a permutation of 15, 14, 13, 12, 10, 8), the last three parsed from `reference/02-character-creation.md` by `parseClassTablesMd` (`scripts/pack/parse.ts`); the pack build writes every class into the pack for them, and `mergeCatalog` keeps the SRD class. The spell and item gaps (2026-11-07) added, all optional with no migration step: `Spell.dc`/`atkB` (an item spell's own save DC and attack bonus, read first by `spellSaveDcFor`/`spellAttackFor`; a Spell Scroll's come from `SCROLL_NUMBERS`), `Spell.chg`/`chgMax`/`castLvl` (casting from the item's charges, `castFromItem`; `castSpell` refuses any item spell), all in `SPELL_FIELDS`; speed grant `floor` (the walk Speed is at least `val`); `checkAdv` target `init` (`initiativeAdv`); value form `'@L:V,…'` (a table keyed by the slot level of the cast); `Item.reads` (a manual's score, `ITEM_FIELDS`; `readManual` turns it into a Feature with a cap-30 `abil` grant); `atkBonus`/`dmgBonus` field `onItem` (only the weapon in `castFx[from].item`, set by `setFxItem`: Magic Weapon); and top-level `castFx` (`Record<link, FxState>`: `lvl` the slot level of the cast, `item` the item it is on). Companions (2026-11-07), all optional with no migration step: top-level `creatures` (`Creature[]`, cleaned by `cleanCreature`/`CREATURE_FIELDS`, with `atk` and `conds` let past `isEntry` and cleaned by `cleanAtk`; absent by default like `castFx`; an older offline copy drops it, accepted), `Spell.makes`/`single` (`SPELL_FIELDS`) and `Feature.makes` (`FEATURE_FIELDS`). `castFx` is not in `blankCharacter()` or the samples: the frozen v2 fixture has no such key and must load unchanged. Readers use `c.castFx ?? {}`; `migrate()` copies it, and `normalize()` keeps an entry only while its effect is on (`isOn`) with a level 1–9 and an item still in `inv`, and deletes the key when it is empty or not an object.
- Entries that can be granted carry `from` (and `srcKind`/`srcName`, `when`, `minLvl`, `needEq`/`needAtt`, `linked`); grants that aren't entries of a list live in `c.grants`. Every change runs through `normalize()` (in `update()` and at the end of `migrate()`): resource and item-charge counts at most their maximum, HP at most `maxHpOf`.
- Backup file: `{app:'dnd-character-sheet', version:1, exportedAt, characters:[Character…], unreadable?:[{key,text}…]}`. A sheet key holding anything but a character opens blank with a notice, after its raw text is copied once to `dnd-sheet-v3:<id>:unreadable` (never listed as a character, kept when the character is deleted); `unreadable` carries such text so a backup holds it, and import ignores it. `initialStore()` lists every sheet key, so a damaged index loses no character. Launch: with no character of your own nothing opens (the welcome screen), not even an example; else an open example (`active` naming one) reopens, else the last character of your own (`Store.c` null, `EMPTY_STORE`: the welcome screen; `persistStore` then writes only the index with `active: ''`, and `update` does nothing). Deleting the last own character gives the same empty store. Import adds the characters next to the existing ones (new ids). Export uses the share sheet on iPad, or a download elsewhere.
- Cast results (spec 2026-11-07): `castSpell`, `castFree`, `castFromItem`, `castRitual` return `null` when the rules refuse the cast and a patch (possibly `{}`) when it happened; `castFromScroll` returns `null` instead of `c`. `refundFree` is the free-cast give-back at 0. A caller that acts on success (the summon step) computes the cast from the render's `c` in the click handler and applies it as a plain patch (`applyCast` in `ui.tsx`), never inside an `update` function.
- An inline plugin in `vite.config.ts` writes `dist/sw.js` from `scripts/sw-source.ts` (tested in `sw-source.test.ts`). That service worker precaches every built file plus `public/` files (listed in `PUBLIC_FILES`). Pages load network-first, and an error page or a failed fetch falls back to the cached page; only a worker's install writes the offline copy, so it always matches its files. Hashed assets are served cache-first. Add new `public/` files to `PUBLIC_FILES`.

## Rules reference

When implementing or checking a rule, use `reference/` (start at `reference/README.md`) instead of memory.
- **Every new or changed piece of rules logic must be checked against the ruleset in `reference/` before it is committed.** This covers `logic.ts`, rule text shown in the UI (conditions, death saves, rest summaries) and any number the sheet derives (bonuses, DCs, speeds). Cite the page in a comment, as the existing code does (`// ... (PHB p.29)`), and add a test in the matching `logic*.test.ts`. If the app deliberately simplifies a rule, say so in the comment.
- Citations use book pages `(PHB p.N)`; **PDF page = book page − 1**.
- `reference/source/phb2024-fulltext.txt` is the raw OCR text, with `===== PHB page N (pdf page M) =====` markers. Grep it for exact wording.
- Spell entries in `07-spells-*.md` use a fixed field layout, so they can be parsed into data later.
